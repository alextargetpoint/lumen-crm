# Вариации CRM-синка — матрица для публичного запуска

Что может прийти/сломаться при подключении реальных amoCRM / Bitrix, и как мы это держим.
Статусы: ✅ закрыто и покрыто тестом · ⚠️ открыто (риск) · 📋 дизайн для Bitrix · ➖ сознательно не делаем.

Прогон всех ✅: `node tools/crm-mock/roundtrip.js` (28 проверок, 12 сценариев).

---

## A. Авторизация и связь
| # | Вариация | Риск | Статус |
|---|----------|------|--------|
| A1 | Неверный/пустой токен | молчаливый «подключён» при мёртвой связи | ✅ 401 → `connected:false`, `lastOkAt=0`; UI не врёт |
| A2 | Токен отозвали/сменили в процессе | авто-синк долбит мёртвый конфиг | ✅ при провале снимаем connected → тик затихает до ручного переподключения |
| A3 | Rate-limit (amo 7 rps, Bitrix 2 rps) → 429 | потеря пуша, бан | ✅ ретрай с бэк-оффом, уважаем `Retry-After` |
| A4 | Таймаут/зависшее соединение | хендлер висит вечно | ✅ `setTimeout` 20с на запрос + ретрай |
| A5 | 5xx / тех-работы amo | сбой синка | ✅ ретрай 5xx |
| A6 | Неверный поддомен | DNS-ошибка | ✅ ловится как сетевая → ретрай → ошибка в UI |
| A7 | 402 (аккаунт amo не оплачен) | — | ⚠️ сейчас как generic-ошибка; стоит отдельный текст владельцу |
| A8 | Параллельные синки (ручной + авто-тик) | двойной пуш/дубли | ✅ лок по тенанту (409 ручному, тик пропускает) |

## E. Bitrix24 — ✅ ПОСТРОЕН (`server/bitrix.js`, те же гарантии, что amo)
Прогон: `node tools/crm-mock/bitrix-roundtrip.js` (19 проверок). Вся закалка раздела A–D перенесена 1:1. Специфика Bitrix:
- ✅ **Подключение:** входящий вебхук `https://portal.bitrix24.ru/rest/{uid}/{token}/` — токен в URL, OAuth не нужен. Секрет, стрипается из publicSettings (`webhookSet`-флаг).
- ✅ **Сущности:** Lumen-лид → **Deal** (crm.deal). CATEGORY_ID + STAGE_ID вида `C1:NEW`.
- ✅ **Поля:** `UF_CRM_*`, enum через `crm.deal.fields` → **авто-детект** (значение уходит item ID, не текст).
- ✅ **Телефон:** `PHONE:[{VALUE,VALUE_TYPE:'WORK'}]`; дедуп через `crm.duplicate.findbycomm`.
- ✅ **Rate-limit 2 rps:** троттлинг-очередь (~550мс между запросами) + ретрай на `QUERY_LIMIT_EXCEEDED`/503/таймаут.
- ✅ **Пагинация:** `start`-offset, ответ `{result,next}`.
- ✅ **404 (удалённая сделка):** `ERROR_NOT_FOUND_ENTITY` → сброс bitrixId → пересоздание.
- ✅ Дедуп, опт-аут, overlap-окно, лок по тенанту (`tid:bx`), усечение, изоляция — как в amo.
- ⚠️ **Пулл новых сделок Bitrix-происхождения** матчим по bitrixId (наши сделки); матч по телефону для сделок, заведённых в Bitrix руками, требует догрузки контакта — v2 (сейчас такие попадают в `skipped`). Для основного кейса (брокер двигает НАШУ сделку) работает.
- ➖ Батч-метод `batch` (до 50 команд) — оптимизация v2; сейчас троттлинг-очередь (безопасно, но медленнее на огромной базе).
