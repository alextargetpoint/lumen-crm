# WhatsApp + Meta: как подключить и НЕ получить бан

Практический план для Lumen CRM. Цель: первым писать лидам, прогревать номера, гнать цепочки — и чтобы номера не блокировались. Ниже — проверенные схемы (актуально на начало 2026), а не теория.

---

## 0. Развилка: какой канал WhatsApp выбрать

Есть 3 способа, у каждого свой риск бана и стоимость:

| Способ | Что это | Риск бана | Кому |
|---|---|---|---|
| **Cloud API (официальный)** | WhatsApp Business Platform от Meta напрямую или через BSP | **Низкий** (если по правилам) | ✅ Рекомендуется для Lumen |
| **Неофициальный (web.js / эмулятор)** | Автоматизация обычного WhatsApp Web | **Высокий** — баны пачками | Только демо/личное, НЕ для рассылок |
| **BSP-шлюз (Wazzup, 360dialog, Twilio)** | Посредник поверх Cloud API | Низкий | Если не хочется возиться с Meta напрямую |

**Вывод для нас:** Lumen уже написан под **Cloud API** (вебхук `/wa/webhook` в формате Cloud API, адаптер `server/wa.js`). Идём этим путём. Референс Sou1/RED тоже сидит на amoCRM + Wazzup (BSP поверх Cloud API), никаких эмуляторов — это подтверждает выбор.

> ⚠️ Главное правило анти-бана: **бан прилетает не за «автоматизацию», а за то, что тебя помечают спамом (block/report).** Cloud API легален для рассылок — блокируют за низкое качество (люди жмут «заблокировать»), а не за факт отправки.

## A. Официальный путь — Cloud API напрямую (наш основной)

### Шаг 1. Аккаунты (день 0, $0)
1. **Meta Business Manager** (business.facebook.com) — если нет, создать на компанию.
2. **WhatsApp Business Account (WABA)** внутри Business Manager → раздел WhatsApp.
3. **Приложение** на developers.facebook.com → добавить продукт «WhatsApp».
4. Верификация бизнеса (Business Verification) — по документам компании. **Без неё лимиты низкие** и часть шаблонов недоступна. Занимает 1–3 дня, делать сразу.

### Шаг 2. Номер телефона
- **Только чистый номер, которым НЕ пользовались в обычном WhatsApp** (или предварительно удалить аккаунт WhatsApp на нём). Идеально — новая SIM/виртуальный номер под каждый WABA.
- Номер регистрируется в Cloud API → получает `Phone Number ID`. С этого момента **обычный WhatsApp на этом номере не работает** — он живёт только через API. Это нормально (то самое «выкидывание номера», не бан).
- **Не переносить старый рабочий номер с историей** — если по нему уже были жалобы, они переедут.

### Шаг 3. Токен
- Для теста — временный токен (24 ч) из панели приложения.
- **Для боя — System User token (постоянный):** Business Settings → System Users → создать → выдать роль на WABA и приложение → сгенерировать токен с правами `whatsapp_business_messaging` + `whatsapp_business_management`. Он не протухает.

### Шаг 4. Подключить к Lumen
В Lumen → раздел **«Подключения»** заполнить:
- `Phone Number ID`
- `WABA ID`
- `System User token`
- `Webhook Verify Token` (в Lumen уже дефолт `lumen-verify` — вписать его же в настройках вебхука приложения Meta).

Технически в `.env` / настройках это ложится в `settings.wa = { mode:'cloud', phoneId, wabaId, token, ... }`. После включения адаптер `wa.js` шлёт реальные сообщения и принимает статусы/входящие через `/wa/webhook`.

**Вебхук:** в приложении Meta → WhatsApp → Configuration → Callback URL = `https://<домен>/wa/webhook`, Verify Token = тот же. Подписаться на поля `messages`. Для локалки — через туннель (`com.lumen.tunnel`, cloudflared) URL временный; для боя — постоянный домен (Railway).

## B. Быстрый путь — BSP-шлюз (если не хочется возиться с Meta)

**Wazzup** (популярен в СНГ-недвижке, как у Sou1) или **360dialog** / **Twilio**:
- Регистрируешься у BSP, они проводят номер через Cloud API за тебя, дают API-ключ.
- Lumen шлёт через их REST вместо прямого Graph API (нужен тонкий адаптер в `wa.js`, ~день работы).
- Плюс: меньше возни с Meta, часто дешевле старт. Минус: +комиссия BSP поверх Meta.

**Рекомендация:** старт — прямой Cloud API (уже готов в коде). Если Meta-верификация буксует или нужен быстрый запуск — Wazzup/360dialog.

## C. АНТИ-БАН: прогрев номеров и правила отправки

Это самое важное. Бан = много block/report + резкий объём с холодного номера.

### C1. Прогрев нового номера (первые 2–3 недели)
Meta даёт **тиры качества** и лимиты, которые растут при хорошем поведении:
- Старт: **250 уникальных получателей / 24 ч** (business-initiated).
- Далее авто-повышение: 1 000 → 10 000 → 100 000 → без лимита — **если качество зелёное** (Quality Rating: High/Green).

**Схема прогрева:**
1. **Неделя 1:** 20–40 сообщений/день, только по **тёплым** (кто сам оставил заявку, ждёт ответа). Никаких холодных рассылок.
2. **Неделя 2:** 60–120/день, добавляем дожимы по ответившим.
3. **Неделя 3+:** плавно к лимиту тира, следим за Quality Rating в WhatsApp Manager.
4. Держать **высокую долю входящих ответов** — Meta это видит как «живой полезный номер». Диалог > веерная рассылка.

В Lumen это уже поддержано: пул номеров с полями `quality`, `tier`, `dayLimit`, `warmupDay`, `state: warming/active/quarantine`; движок шлёт пачками с паузами. **Держать `dayLimit` реальным по тиру, не задирать.**

### C2. Правила первого касания (критично)
- **Холодному лиду (кто не писал сам) первым сообщением — ТОЛЬКО одобренный шаблон (template), категории.** Свободный текст первым — только внутри **24-часового окна** после сообщения клиента.
- **24-часовое окно (Customer Service Window):** клиент написал → 24 ч можно отвечать свободным текстом. Окно закрылось → снова только шаблон.
- **Opt-in:** формально нужно согласие на переписку. Заявка через Meta Lead Form / сайт с галочкой = согласие. Не пиши тем, кто не оставлял контакт.

### C3. Категории шаблонов и цена (×4 разница!)
- **Utility** (сервисные: подтверждение заявки, статус, напоминание о встрече) — дёшево, модерируются легко.
- **Marketing** (промо, «новые проекты с рассрочкой») — **в ~4 раза дороже** и строже модерация, легче словить block.
- **Authentication** — коды (нам не нужно).

**Тексты цепочек писать под Utility-модерацию:** первое касание оформлять как сервисный ответ на заявку («Вы оставили заявку по …, помогу подобрать»), а не как рекламу. Меньше «уникальных возможностей» и капса — иначе Marketing + риск block. Реанимацию спящих (`tpl_wake_*`) — да, это Marketing, но она по базе, что уже давала согласие.

### C4. Что снижает Quality Rating (избегать)
- Идентичный текст веером многим (шаблонность → спам-флаг). → **ротация формулировок** (у нас есть в comment-autoReply, применить и к цепочкам).
- Резкий рост объёма с нового номера. → прогрев.
- Много номеров-жалоб подряд. → чистить базу от «не пишите» (стоп-слова в Lumen уже есть).
- Слать в неудачное время / ночью. → **тихие часы по поясу лида** (в Lumen уже реализовано).
- Ссылки/вложения в первом холодном касании. → сначала текст, ссылку — после ответа.

### C5. Мультиномерная схема (масштаб)
- **1 номер = 1 гео / 1 поток.** У Lumen пул по гео (Дубай/Бали/Пхукет/Испания) — правильно.
- Не лить весь объём с одного номера — распределять, держать каждый в зелёном тире.
- Номер ушёл в жёлтый/красный (`quarantine`) — снять с рассылок, дать «отдохнуть» на входящих.
- Резервные номера в прогреве всегда наготове (в пуле уже есть `state:'warming'` и резерв).

## D. Первичная последовательность запуска (сводка)

1. Business Manager + WABA + приложение + **Business Verification** (сразу).
2. Чистый номер → регистрация в Cloud API → `Phone Number ID`.
3. **System User token** (постоянный).
4. Заполнить «Подключения» в Lumen + настроить вебхук (`/wa/webhook`, verify token).
5. Создать и отправить на модерацию **Utility-шаблоны** первого касания и напоминаний (RU/EN). Дождаться approved.
6. **Прогрев 2–3 недели** по схеме C1 — только тёплые, растим тир.
7. Включить цепочки на боевой поток; следить за Quality Rating в WhatsApp Manager.
8. Масштабировать: добавлять номера по гео, каждый через прогрев.

## E. Стоимость (ориентир, на агентство ~500 лидов/мес)

- Meta берёт за **conversation** (окно 24 ч), цена зависит от страны и категории. Utility кратно дешевле Marketing.
- При 500 лидов/мес: **≈ $70–180/мес** переменной части (главная вилка — доля Marketing vs Utility шаблонов = ×4). Плюс STT/ИИ (Whisper/Gemini/OpenAI), Railway-хостинг (~$5/инстанс), телефония по желанию.
- **Cost-safe дефолт:** тексты цепочек — под Utility; Marketing — только адресная реанимация базы. Так укладываемся в нижнюю границу.

Детали онбординга агентства и переезд Mac→Railway — в `ROLLOUT.md`.

## F. Чек-лист «почему забанило / не отправляется»

- Номер использовался в обычном WhatsApp и не удалён → конфликт. Взять чистый.
- Business не верифицирован → низкие лимиты, часть шаблонов недоступна.
- Первое холодное сообщение свободным текстом (не шаблон) → отбивка/риск. Только template вне 24ч-окна.
- Шаблон в Marketing вместо Utility → дорого + block. Переоформить как сервисный.
- Резкий объём с нового номера → жёлтый тир. Вернуться к прогреву.
- Идентичный веерный текст → спам-флаг. Ротация формулировок.
- Много «заблокировали/пожаловались» → чистить базу, снизить темп, проверить оффер.
