# Телефония, номера и прогрев — схема подключения и комплаенс

Документ-план: как в Lumen CRM подключаются телефония, WhatsApp-номера и прогрев, и как при этом **не сломать будущее официальное одобрение** (Meta/WhatsApp Business Platform). Готовим заранее, чтобы при онбординге агентства всё было предсказуемо.

## 0. Два контура — держать раздельно

| Контур | Что это | Риск для одобрения Meta |
|---|---|---|
| **Белый (официальный)** | WhatsApp Cloud API (Business Platform), верифицированный WABA, шаблоны | Нулевой — это и есть предмет одобрения |
| **Серый (прогрев/QR)** | Эмулятор прогрева по протоколу WhatsApp Web, переписка номеров между собой | Высокий — нарушает ToS. **Не смешивать с боевым номером** |

⭐ **Главный принцип:** боевой номер агентства идёт ТОЛЬКО через белый контур. Прогрев — ТОЛЬКО на отдельных вторичных номерах. Эти два множества номеров не пересекаются никогда.

## 1. Приём лидов (входящий) — белый контур
1. Meta Ads → цель **«Лид-формы» (Instant Forms)** или **Click-to-WhatsApp**.
2. Форма → интегратор (Albato / Make / Zapier) → наш **Webhook приёма** (`/hooks/lead?key=SECRET`, гибкий маппинг полей).
3. Лид падает в CRM, дедуп по номеру, мэтч на объявление по `ad_id`.

## 2. Отправка сообщений (исходящий) — белый контур
1. Агентство заводит **WhatsApp Business Platform** (Cloud API) на свой боевой номер: Business Manager → WhatsApp → создать WABA → верификация бизнеса → подключить номер (номер «отвязывается» от обычного приложения — это штатно, не бан).
2. Токен (System User, постоянный) + Phone Number ID → в «Подключения».
3. Первые сообщения вне 24-часового окна — только по **одобренным шаблонам** (utility/marketing). ⚠️ utility ≈ ×4 дешевле marketing и легче проходит модерацию → тексты цепочек писать под utility-тон.
4. Meta CAPI (обратные конверсии) — по официальному Graph API, PII хешируется.

## 3. Телефония (звонки) — план
- Провайдеры-кандидаты: **Zadarma / Twilio / Telnyx** (SIP + запись).
- Вебхук `/hooks/call?key=SECRET` (номер + record_url) → лид по хвосту номера → запись → **Whisper-транскрипт** в карточку.
- ⚠️ Whisper валидирует формат по расширению имени файла — брать ext из URL записи.
- Real-time перевод звонков (RU↔EN) — отдельный аддон поверх телефонии (аудио-мост), платный, off by default.

## 4. Прогрев — серый контур, с жёсткими предохранителями
Эмулятор (раздел «Номера») подключает номера по QR (WhatsApp Web) и заставляет их переписываться между собой с задержками по регламенту.

**Предохранители в продукте (обязательны, чтобы не топить одобрение и снизить панику):**
1. **Двойное согласие** перед запуском: (а) принятие рисков + снятие ответственности с Lumen; (б) подтверждение, что на прогрев ставятся **только вторичные номера**, не основной и не WABA-номер. Без обоих чекбоксов старт заблокирован (сервер-гейт `/warmup/start` при отсутствии consent → 400).
2. **Явная плашка-предупреждение** в модалке и в разделе: «Не ставьте основной номер / номер с клиентскими чатами / привязанный к Cloud API».
3. **Задержки и лимиты** по частоте (имитация живой активности, не спам-всплеск).
4. Реальная отправка идёт через **внешний мост** (не с нашего сервера) — Lumen оркеструет и ведёт журнал, но не является отправителем.

**Почему это важно (пользовательская психология):** даже с галочкой согласия при блокировке номера будет паника и тикеты в поддержку. Поэтому: (1) в онбординге явно требуем выделенные SIM/номера под прогрев; (2) в UI повторяем это на каждом шаге; (3) в договоре/оферте — пункт про серые методы и ответственность клиента.

**Изоляция от одобрения:** наличие функции прогрева ВНУТРИ CRM само по себе одобрению Cloud API не мешает, пока (а) боевой WABA-номер никогда не идёт через QR-эмулятор; (б) прогрев не использует официальный Graph API; (в) это отдельный модуль, который агентство включает осознанно. При подаче на Tech Provider / Embedded Signup — прогрев не декларируется как часть интеграции с Meta (это внешний инструмент клиента).

## 5. Онбординг номеров агентства — чеклист
- [ ] Боевой номер → Cloud API (белый контур), токен+Phone ID в «Подключения».
- [ ] 1–3 **отдельных вторичных** номера/SIM выделены под прогрев (не основной!).
- [ ] Шаблоны первого касания/дожима поданы на модерацию (utility-тон).
- [ ] Телефония (по желанию) → вебхук записи → транскрипт.
- [ ] Клиент ознакомлен и подписал: серые методы = его ответственность.

## 6. Масштаб
1 агентство = 1 инстанс Railway + свой WABA. Цель — статус **Meta Tech Provider** (Embedded Signup), чтобы подключать WABA клиентов в пару кликов без ручной возни.
