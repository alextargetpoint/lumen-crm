# Lumen — единый SaaS-контур связи (телефония + WhatsApp + прогрев + покупка номеров)

**Цель:** агентство подключается к Lumen один раз и получает всё «под ключ» — звонки, WhatsApp Cloud API (белая рассылка), прогрев номеров и покупку номеров **прямо в дашборде**, с минимумом ручных телодвижений. Ниже — целевая архитектура и что уже сделано.

---

## 1. Мультитенантность: субаккаунт на агентство

- **Мастер-аккаунт Twilio = наш** (Lumen). На каждое агентство создаём **Subaccount** (`POST /Accounts.json`).
- Плюсы: изоляция номеров/звонков/биллинга по агентствам, единый счёт нам от Twilio, мы выставляем агентству свою цену (pass-through + наценка). Агентство не заводит свой Twilio — всё через нас.
- В Lumen у тенанта хранится: `telephony.provider='twilio'`, `accountSid` (его субаккаунт AC…), ключ доступа (наш API Key SK… с правами на субаккаунт, или Auth Token субаккаунта), `fromNumbers[]` (пул купленных номеров), `fromNumber` (дефолт).
- То же для WhatsApp: у тенанта — свой WABA (WhatsApp Business Account) + phone_number_id, привязанные через Embedded Signup (см. §4).

> Пока (MVP) работаем на одном аккаунте с ручными ключами. Субаккаунты — следующий шаг для настоящего SaaS.

---

## 2. Телефония (✅ ядро готово)

Реализовано в `server/index.js`:
- **Click-to-call**: звоним брокеру → TwiML соединяет с клиентом → запись → авто-транскрипт в карточку лида. Дисп. `initiateCall` (twilio/telnyx).
- **Гео caller-ID (local presence)**: клиент видит номер своей страны (`pickCallerId` по коду страны) → выше отклик. Нужны купленные номера по странам.
- **Вебхуки**: `/twilio/voice`, `/twilio/recording`, `/twilio/status`, `/twilio/inbound`.
- **Покупка номеров в дашборде**: `GET /api/telephony/numbers/search?country=FR`, `POST /api/telephony/numbers/buy`, `GET /api/telephony/numbers`, `POST /api/telephony/test`.

**Осталось по телефонии:** UI в «Подключения → Телефония» — поля Account SID + ключ, кнопка «Проверить», раздел «Номера» (поиск по стране → купить в 1 клик → номер падает в пул гео-подбора). Инбаунд-маршрутизация и голосовая почта — по желанию.

---

## 3. Покупка номеров — единый раздел «Номера»

Один экран, где агентство покупает номера под РАЗНЫЕ цели:
- **Для звонков** — Twilio DID нужной страны (гео caller-ID). ✅ API готов.
- **Для WhatsApp Cloud API** — номер, который пройдёт верификацию Meta (см. §4). ⚠️ Не любой VoIP годится: Meta режет дешёвые VoIP. Варианты: (а) Twilio-номер, зарегистрированный как WhatsApp Sender через Twilio-BSP; (б) «чистый» номер от сервиса, который вы вчера подключили (ждёте ответа) — как только ответят, добавим его как источник.
- **Для прогрева** — номер под браузерный WA-прогрев (§5).

UI: выбор цели → страна/тип → поиск → купить → номер привязывается к нужному каналу.

---

## 4. WhatsApp Cloud API — онбординг в минимум кликов (Embedded Signup)

Чтобы «через нас по-быстрому», а не 20 шагов в Meta:
- Становимся **Meta Tech Provider / Solution Partner**. Тогда агентство подключает WhatsApp через **Embedded Signup** — попап Meta прямо в нашем дашборде: логин в FB → выбор/создание WABA → выбор номера → OTP-верификация → готово. Мы получаем `waba_id` + `phone_number_id` + системный токен → кладём в конфиг тенанта → Cloud API работает.
- **Верификация номера**: в Embedded Signup Meta сама шлёт OTP (SMS/звонок) на номер. Поэтому номер должен принимать OTP и не быть «грязным» VoIP. Надёжно: Twilio-номер (как WA-sender через Twilio) или чистый мобильный/сервисный номер.
- **Два пути реализации:**
  - **A. Через Twilio как BSP** — Twilio Senders API регистрирует номер как WhatsApp-отправителя, верификация внутри Twilio. Плюс: один провайдер и на звонки, и на WA. Минус: тариф Twilio поверх Meta.
  - **B. Напрямую Meta Cloud API** (у нас уже есть в CRM `settings.wa`: phoneId/wabaId/token/webhook) + **наш Embedded Signup** как Tech Provider. Плюс: дешевле (платим Meta напрямую), это и есть «белая рассылка». Минус: нужно пройти статус Tech Provider у Meta (инструкция — `docs/META-ADS-APP-REVIEW.md` по логике та же, но продукт WhatsApp).

> Рекомендация: **B (прямой Cloud API + Embedded Signup)** для белой рассылки и минимальной цены; номер под него — Twilio или чистый. У нас уже есть приёмник входящих WA и мост — не хватает только Embedded Signup-попапа и авто-заполнения `settings.wa`.

**Осталось по WA:** (1) статус Meta Tech Provider; (2) кнопка «Подключить WhatsApp» → Embedded Signup → авто-заполнение `settings.wa`; (3) выбор источника номера (Twilio-sender / купленный / свой).

## 5. Прогрев номеров (браузерный WA-коллектор)

- Уже есть сервис прогрева на Mac (launchd, не сервер — анти-бан). Схема: купил номер → **прогрел** (постепенная активность между своими номерами/лайв-чаты) → пустил в рассылку. Это снижает риск бана свежего WA-номера.
- В SaaS: после покупки номера под WA — кнопка «Поставить на прогрев» → номер уходит в очередь коллектора; статус прогрева виден в дашборде; по готовности — «готов к рассылке».
- Важно: прогрев и Cloud API — разные каналы одного номера; следим, чтобы номер не был одновременно в неофициальном web-клиенте и в Cloud API (Meta не любит).

**Осталось:** связать статус коллектора с дашбордом (очередь/готовность) и кнопку «на прогрев» у номера.

---

## 6. Онбординг тенанта — целевой поток (минимум действий)

1. Регистрация агентства в Lumen.
2. Экран **«Подключить связь»** — три плитки:
   - **Телефония**: «Включить» → создаём субаккаунт Twilio → «Купить номер» (страна) → готово к звонкам с гео caller-ID.
   - **WhatsApp**: «Подключить WhatsApp» → Embedded Signup (1 попап) → номер верифицирован → белая рассылка работает.
   - **Прогрев** (опц.): «Прогреть новый номер» → очередь коллектора.
3. Всё. Дальше клиенты звонят/пишут, звонки и WA падают в карточки лидов, рассылки идут в белую.

Принцип: **никаких переходов в чужие кабинеты** — покупка номеров, верификация WA и прогрев инкапсулированы в нашем дашборде.

---

## 7. Биллинг (кто за что платит)

- Мы платим Twilio/Meta по факту (звонки, номера, WA-разговоры).
- Агентству — единый счёт от нас: подписка Lumen + расходники по себестоимости провайдеров (или с наценкой). У нас в CRM уже есть модель расходников (WhatsApp — Meta, ИИ-токены — провайдер, телефония — провайдер), списание в конце расчётного месяца.
- Субаккаунты Twilio дают пер-агентский учёт расхода «из коробки».

## 8. Дорожная карта (что делаем по шагам)

1. ✅ **Телефония-ядро**: click-to-call, гео caller-ID, API поиска/покупки номеров.
2. ⏳ **UI телефонии**: поля ключей + «Номера» (поиск→купить в 1 клик). *(след. шаг)*
3. ⏳ **Twilio Subaccounts**: авто-создание субаккаунта на тенанта.
4. ⏳ **WhatsApp Embedded Signup**: попап подключения + авто-`settings.wa` (стать Meta Tech Provider).
5. ⏳ **Раздел «Номера»**: единая покупка под звонки/WA/прогрев.
6. ⏳ **Прогрев в дашборде**: очередь коллектора + статус.
7. ⏳ **Биллинг per-tenant**: расходники из субаккаунтов + WA-conversations.

### Что нужно от вас сейчас (чтобы включить телефонию)
- **Account SID (AC…)** из Twilio Console → Account Info (API Key SK… + Secret вы уже дали — они для авторизации; AC… нужен для пути REST).
- **Номер «От»**: купить один Twilio-номер (или дайте страну — куплю через `/api/telephony/numbers/buy`, как только будет Account SID).
- **Какой сервис** вы подключили «для покупки WhatsApp-номеров» — назовите, добавлю его как источник номеров под WA.
