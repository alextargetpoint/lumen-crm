# Lumen · Брокеры: безопасность, учётки, методики управления

Обновлено: 23.07.2026 (v0.24). Что уже работает — помечено ✅, роадмап — ◻︎.

## 1. Модель угроз агентства

Главная ценность агентства — база лидов. Главные риски:
1. **Увод базы** уходящим брокером (главная боль рынка).
2. Слив контактов конкуренту без увольнения.
3. Потеря лида из-за медленного касания (не безопасность, но та же цена).

## 2. Система учёток (реализовано)

- ✅ **Две роли**: `owner` (пароль агентства) и `broker` (личный PIN ≥ 6 символов, задаёт владелец в карточке брокера). Один экран входа: система сама понимает, кто вошёл.
- ✅ **Broker видит только своих лидов** — фильтрация на СЕРВЕРЕ (не в UI): списки, карточки, события ленты. Чужой лид → 403 + запись в журнал.
- ✅ **Закрытые поверхности** для роли broker: настройки, шаблоны, цепочки, номера, реклама, кампании реанимации, брокеры, аудит, экспортные мосты. Меню урезано автоматически.
- ✅ **Аудит-лог** (`db.audit`, 500 записей): вход, открытие карточки, попытка доступа к чужому лиду, выдача PIN, kill-switch. Журнал — на странице «Брокеры» (только владелец).
- ✅ **Kill-switch**: тумблер «Доступ» в карточке брокера — мгновенно гасит его сессии, блокирует PIN, переназначает активных лидов наименее загруженным, пишет в журнал и ленту.
- ◻︎ Маскировка телефона до первого касания (брокер видит +971•••••67, звонок — через кнопку) — анти-слив уровня paranoid.
- ◻︎ Логирование копирования телефона/экспорта; rate-limit на массовые открытия карточек («скан базы»).
- ◻︎ Пер-брокерный WhatsApp-подключение (сообщения от имени агентства, номер принадлежит компании — уже соблюдается архитектурой Cloud API).

## 3. Методики эффективного управления (что внедрено)

- ✅ **Speed-to-lead SLA**: настройка «SLA брокера, минут» (Автоматизации). Не коснулся лида за N мин после передачи → эскалация в ленту (+ мгновенный алерт в TG, если включён); за 2×N → **shark tank**: лид автоматически уходит следующему свободному брокеру. Касание = ручное сообщение или назначенная встреча.
- ✅ Авто-распределение: по загрузке / очереди / **сменам с пер-дневными интервалами**.
- ✅ Авто-задача «позвонить за 30 мин» при передаче + саммари с цитатами клиента.
- ✅ No-show возврат в работу; поведенческие триггеры (открыл подборку → «лучший момент для звонка»).
- ◻︎ Лидерборд брокеров: скорость первого касания, конверсия handover→сделка, no-show rate (данные уже копятся: handoverAt, meetings, audit).
- ◻︎ Пайплайн-гигиена: stale-детектор (лид без движения X дней у брокера → напоминание → пул).
- ◻︎ Планёрка-отчёт владельцу: еженедельная сводка по брокерам в TG (движок отчётов уже есть).

## 5. Инварианты (не ломать)

- Роль проверяется НА СЕРВЕРЕ на каждом эндпоинте; UI-скрытие — только косметика.
- `pinHash` никогда не сериализуется наружу (`brokerPub`).
- Kill-switch обязан: гасить сессии + блокировать логин + переназначать лидов — всё три, атомарно.
- Любое действие брокера с чувствительным ресурсом — в `db.audit`.
