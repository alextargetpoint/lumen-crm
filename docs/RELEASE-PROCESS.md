# Lumen — регламент выката обновлений (SaaS)

Обновлено: 14 сентября 2026. **Железное правило: обновление НЕ уходит в прод, пока гейт выката не «PASS».**
Это защита боевых данных клиентов — как в дашборде TP, где правка входа/приватности клала систему.

## Гейт выката (одна команда)

```
node test/release-gate.mjs "что меняли"
```

Прогоняет обязательные проверки и пишет `release.json` (виден в админке → вкладка «🚀 Релиз»):
- **Изоляция тенантов и авторизация** — `test/saas-auth.mjs` (83 инварианта): регистрация, изоляция агентств, роли, admin, suspend, impersonate.
- **Антивзлом (стресс)** — `test/security-stress.mjs` (34 атаки): IDOR, инъекции, подделка сессий, брутфорс, кросс-тенант.

Вердикт: **PASS** → можно пушить. **FAIL** → пуш запрещён, чинить тесты.

## Полный процесс выката

1. **Правки локально.** Коммить свободно (коммит ≠ деплой).
2. **Призма качества** (см. память `lumen-quality-lens-every-task`): анимация Atelier · безопасность · контраст во всех пресетах · функц-тест · EN-перевод нового текста.
3. **Гейт:** `node test/release-gate.mjs "…"` → должен быть PASS.
4. **Локальная проверка в браузере** на чистом временном `DATA_DIR` (НЕ :5077 — там дев юзера): вход → ключевой сценарий правки → 0 ошибок консоли. Для правок логина — логин-матрица (регистрация/вход owner+broker/сброс/смена пароля).
5. **Бэкап перед рисковой операцией** (массовые изменения данных): снимок уже автоматизирован (ежечас + PRE-WIPE), для ручных — `store.backupTenant(tid,'manual')`.
6. **Пуш** `git push` → Railway авто-выкатит (пуш = деплой = деньги; копи́ть и пушить пачкой проверенного).
7. **Сверить прод:** версия `app.js?v=N` на `app.lumen247.com/index.html` == локальной; вкладка «Релиз» в админке покажет совпадение версий.
8. **Записать выкат** в журнал (админка → Релиз → «Записать выкат»).

## Инварианты, которые нельзя ломать (см. docs/AUTH-AND-DATA-INFRA.md §9)
- «Страница с данными ⇔ валидная сессия; иначе окно входа, НИКОГДА молчаливый пустой каркас».
- Новые поля данных — с дефолтом в `ensureTenantDefaults`, без миграции старые записи не ломать.
- Изменения правил доступа — покрывать тестом изоляции (чужой тенант/роль → 403).
- `data/` (рантайм-БД с секретами) НИКОГДА не коммитить.

## Что видно в админке (вкладка «🚀 Релиз»)
- Статус последнего гейта (PASS/FAIL), версия в гейте vs версия на проде, коммит, дата, результаты сьютов.
- Правило выката и краткий процесс.
- Журнал выкатов (что и когда ушло в прод).
