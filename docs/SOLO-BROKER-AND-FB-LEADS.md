# Lumen для сингл-брокера + нативный сбор лидов из Facebook

Документ фиксирует конфигурацию продукта под **одного брокера** (не агентство) и архитектуру
**нативного подключения Facebook Lead Ads** (вход через Facebook → выбор бизнес-страниц → приём
лидов с полной разметкой кампания/adset/ad + UTM). Grounded в текущий код (`public/app.js`,
`server/`), не абстрактно.

---

## 1. Издание «Solo» (single-broker)

### Что это
Флаг `STATE.settings.agency.edition === 'solo'` (уже существовал, был почти пустой). Одно
пространство одного человека: его лиды, диалоги, база, встречи, задачи, своя реклама, контент,
автоматизация. Никакой «команды».

### Что убрано в solo (сделано, `SOLO_HIDDEN_PAGES` в app.js)
`feed` (лента), `hr` (подбор), `brokers`, `roles` (роли и доступы), `control` (контроль команды),
`learn` (академия агентства — обучение сотрудников), `mediaplan` + `adsAnalytics` (подрядчики
трафика, план/факт — это агентская история), `comments`.

Реализовано единым предикатом `pageHiddenForUser(pg)` — применяется к пунктам сайдбара,
под-пунктам пространств, вкладкам `ws-tabs`, поиску по разделам (⌘K) и к дефолтной вкладке
пространства (пространство «Реклама» теперь открывается сразу на «Атрибуция·CAPI», а не на скрытом
медиаплане). Командное издание не тронуто — флаг обратимый.

### Что осталось (ядро сингл-брокера)
Обзор · Воронка · Реанимация базы · Диалоги (+ переводчик звонков) · База (объекты/подборки) ·
Встречи · Мои задачи · Реклама (атрибуция) · Аналитика (лиды/продажи) · Контент-цех ·
Автоматизация (квалификатор/цепочки/плейбук/академия продаж/студия/оценка звонка/шаблоны) ·
Настройки (подключения/номера/профиль/оплата).

### Следующие срезы (не сделано — план)
1. **Overview под solo** — убрать «Штаб руководителя» (owner-блоки: срез по команде, доска
   лидеров, распределение по брокерам, перегруз брокеров) под `IS_SOLO()`; вместо них личные
   виджеты: мои горячие лиды, кто ждёт ответа, задачи на сегодня, встречи сегодня, мой винрейт
   месяца, реанимация (сколько «спящих» можно поднять), приток лидов по источникам/кампаниям.
   Точка: `PAGES.overview`, блок «ШТАБ РУКОВОДИТЕЛЯ» (~строка 2254 app.js).
2. **Упрощение лейблов** — «Передать брокеру» → «Взять в работу» уже есть; пройтись по всем
   «команда/брокер/агентство»-формулировкам в solo (напр. «Профиль агентства» → «Мой профиль»).
3. **Активация издания** — сейчас `edition` только в state. Нужна точка включения:
   - онбординг: первый экран «Вы один / у вас команда» → пишет `edition`;
   - настройка в «Профиле» для переключения;
   - тариф Solo в billing (дешевле, 1 место, без ролей/HR/подрядчиков).
4. **Серверный гейт** — solo не должен позволять создавать брокеров/роли на API (не только
   прятать в UI). Проверка `edition==='solo'` на `/api/brokers*`, `/api/roles*`.

### Решения, принятые за вас
- `comments` скрыл в solo (командный поток комментариев); если это лента комментов соцсетей,
  которая нужна соло — верну одной строкой.
- `studio`, `academy` (продажи), `callReview`, `parlo`, `playbook`, `templates` — ОСТАВИЛ: полезны
  одному брокеру. `learn` (академия агентства = обучение команды) — убрал.
- `billing` оставил (соло тоже платит подписку).

## 2. Нативный сбор лидов из Facebook Lead Ads

### Как сейчас
Приём лидов через webhook/интеграторы (внешний сервис шлёт в наш эндпоинт). Разметки кампании нет
или она частичная.

### Как надо (нативно, без интеграторов)
**Facebook Login → выбор Страниц → подписка на лид-формы → приём лидов realtime + бэкфилл, с полной
атрибуцией.**

#### 2.1 OAuth (вход через Facebook)
- Кнопка «Подключить Facebook» в Настройки → Подключения (solo) / отдельный шаг онбординга.
- Facebook Login с scope: `pages_show_list`, `pages_read_engagement`, `leads_retrieval`,
  `pages_manage_metadata` (для подписки на webhook страницы), `business_management` (если через
  Business Manager), `ads_read` (чтобы тянуть имена кампаний/adset/ad и потратённое).
- Обмен короткоживущего токена на **long-lived user token** → получить **page access tokens**
  (`/me/accounts`). Хранить page-токены пер-tenant (шифровать, как остальные секреты; НЕ в git).

#### 2.2 Выбор страниц/форм
- Показать список Страниц (`/me/accounts`) → пользователь отмечает нужные бизнес-страницы.
- Для каждой выбранной: подписать приложение на поле `leadgen` (`POST /{page-id}/subscribed_apps`
  с `subscribed_fields=leadgen`).
- Опционально: список лид-форм страницы (`/{page-id}/leadgen_forms`) для маппинга полей формы на
  поля карточки лида (имя/телефон/бюджет/гео).

#### 2.3 Приём лида (realtime)
- Meta шлёт webhook на `/fb/leadgen` при новом лиде: `{ leadgen_id, page_id, form_id, ad_id,
  adgroup_id (adset), campaign_id, created_time }`.
- По `leadgen_id` дёргаем `GET /{leadgen_id}?access_token={page_token}` → полные `field_data`
  (ответы формы) + `ad_id`/`campaign_id`.
- Верификация вебхука: `X-Hub-Signature-256` (HMAC SHA256 по app secret) — по образцу нашего
  `/tg/webhook` secret-verify и `/support/webhook`.

#### 2.4 Атрибуция (критично для аналитики)
Сохранять в карточку лида при приёме:
- `campaign_id` + **имя кампании** (резолв через `GET /{campaign_id}?fields=name` с `ads_read`),
- `adset_id` + имя adset,
- `ad_id` + имя объявления + (по возможности) превью креатива,
- `form_id` + имя формы,
- `page_id` + имя страницы,
- UTM: если в объявлении заданы `url_tags`/трекинг-параметры — распарсить (`utm_source/medium/
  campaign/content/term`). Для лид-форм UTM часто нет → синтезируем: `source=facebook`,
  `medium=lead_ad`, `campaign=<имя кампании>`, `content=<имя объявления>`.
- `platform` (facebook/instagram — из `ad`/`publisher_platform`).

Это ложится в существующую модель источников (analytics по источникам/кампаниям в app.js уже есть:
`bestSource`/`byBroker`/funnel). Даст живой срез «какая кампания/объявление приносит лиды и по чём».

#### 2.5 Бэкфилл (история)
Разово при подключении: пройтись по формам (`/{form-id}/leads?fields=...`), затянуть последние
N дней лидов, чтобы аналитика не была пустой. Пагинация + rate-limit.

### Что требует ВАС (не могу сделать без вас)
1. **Meta App Review** — `leads_retrieval` и pages-права требуют верификации приложения в Meta
   (Business verification + App Review со скринкастом сценария). Это ваши действия в
   developers.facebook.com. Без ревью — только тестовые страницы, где вы админ.
2. **App ID / App Secret** — создать/дать приложение Meta (или использовать существующее
   TargetPoint-приложение). Секрет — в env Railway, не в код.
3. **Config webhook** в приложении Meta: callback `https://app.lumen247.com/fb/leadgen`,
   verify-token (сгенерирую), подписка на объект `page` поле `leadgen`.

### Стоимость
- Сам приём лидов из Meta — **бесплатно** (Graph API).
- `ads_read` для имён кампаний/трат — бесплатно.
- Наши расходы — только egress/compute (незначимо). Основной «расход» — ваше время на App Review.

### План реализации (фазы)
- **Ф1 (сервер):** `/fb/oauth/start` + `/fb/oauth/callback` (long-lived + page tokens, хранение
  шифрованно) · `/fb/pages` (список/выбор) · `/fb/leadgen` webhook (verify + retrieve + attribute
  + upsert лид) · маппинг полей формы.
- **Ф2 (UI solo):** карточка «Facebook» в Подключениях: кнопка входа, чекбоксы страниц, статус
  подписки, тумблер «ИИ ведёт новые FB-лиды», журнал последних принятых лидов с кампанией.
- **Ф3 (атрибуция/аналитика):** имена кампаний/adset/ad в карточке лида + фильтры аналитики по
  кампании/объявлению; бэкфилл истории.
- **Ф4:** CAPI обратно (уже есть раздел «Атрибуция·CAPI») — слать события квал/сделка в Meta для
  оптимизации на качество, замкнув контур.
