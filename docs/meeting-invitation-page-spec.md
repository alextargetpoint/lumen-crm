# LumenCRM — ТЗ: клиентская страница-приглашение на встречу + конструктор
Версия 1.0 · 10 октября 2026 · статус: проект требований (адаптировать к фактическому стеку после просмотра кода).

Два варианта клиентской страницы + экран конструктора внутри LumenCRM.
- **Вариант 1 «Компактное приглашение»** (СТАНДАРТ): акцент на времени встречи и подтверждении.
- **Вариант 2 «Личное приглашение»** (альтернатива при первом контакте): акцент на брокере, знакомстве и доверии; рядом мобильная версия.

> Все изображения/данные в макетах — демонстрационные; в проде подставляются из CRM. Надпись «Защищённая ссылка» использовать ТОЛЬКО при реальной проверке доступа. Zoom-кнопка до подтверждения на макете — артефакт; использовать правила состояний из §6.

## 1. Где это в CRM
Основной вход: **Встречи → конкретная встреча → «Страница клиента»**. Доп. вход — из карточки лида, блок ближайшей встречи. Оба открывают ОДИН документ. Отдельную большую секцию с ещё одним конструктором НЕ создавать. Общие шаблоны — **Настройки → Оформление → Страницы встреч**.

## 2. Как брокер создаёт приглашение
1. Создаёт встречу из карточки клиента. 2. Дата/время/длительность/способ подключения. 3. «Подготовить приглашение». 4. Готовая страница с именем клиента, своими контактами, оформлением агентства. 5. При необходимости добавляет подборку, меняет приветствие, публикует ссылку.
Конструктор для каждого приглашения НЕ обязателен — если шаблон устраивает, достаточно предпросмотра и публикации. Отправка клиенту — отдельное действие (копировать ссылку / отправить через канал с предпросмотром сообщения).

## 3. Конструктор
| Область | Функционал |
|---|---|
| Верхняя панель | Клиент, брокер, встреча, сохранение, предпросмотр, публикация |
| Слева | Выбор шаблона, список блоков, порядок, видимость |
| Центр | Живой предпросмотр с редактированием текста на месте |
| Справа | Настройки выбранного блока |
| Над предпросмотром | Компьютер / телефон, просмотр разных состояний встречи |

Клик по тексту — inline-правка. Фото — «Заменить / Кадрировать / Выбрать из подборки». Блоки переставляются мышью или кнопками вверх/вниз. Параметры встречи — спец-поля, не свободный текст. Доп. настройки скрыты до востребования (без слоёв и десятков отступов).

## 4. Библиотека блоков
| Блок | Что настраивается |
|---|---|
| Приветствие | Заголовок, описание, обращение по имени |
| Встреча | Компоновка; данные из записи встречи |
| Брокер | Компактная визитка или расширенная карточка |
| Обложка | Фото, кадрирование, показ/скрытие |
| План встречи | Короткие пункты обсуждения |
| Подборка объектов | Ссылка на существующую клиентскую подборку |
| Материалы | PDF, презентация, памятка, разрешённая ссылка |
| Вопрос перед встречей | Необяз. «Что хотите обсудить?» |
| Инструкция подключения | Короткая подсказка клиенту |
| Итоги встречи | Добавляются брокером после разговора |

По умолчанию: приветствие, встреча, брокер. Остальные блоки — при наличии содержания (пустые карточки не показываются). Дату, часовой пояс и основное действие на действующем приглашении скрыть нельзя.

## 5. Источники данных
| Источник | Данные |
|---|---|
| Карточка клиента | Имя, язык, согласованный часовой пояс |
| Запись встречи | Время, длительность, формат, статус, ссылка подключения |
| Профиль брокера | Фото, имя, должность, публичные контакты |
| Настройки агентства | Логотип, оформление, шаблон по умолчанию |
| Подборки клиентов | Опубликованные презентации и материалы |

Локальная правка приветствия НЕ меняет карточку клиента; правка описания брокера на одном приглашении НЕ перезаписывает его общий профиль. Дата и Zoom-ссылка — через «Изменить встречу». Внутренние комментарии/задачи/квалификация/переписка на публичную страницу НЕ передаются.

## 6. Состояния (страница меняется со встречей)
| Состояние | Что видит клиент |
|---|---|
| Ожидает подтверждения | «Подтвердить участие» + «Предложить другое время» |
| Подтверждена | Подтверждение, дата, календарь, материалы |
| Приближается начало | Основная кнопка «Подключиться к встрече» |
| Запрошен перенос | «Запрос отправлен брокеру»; прежнее время — ожидает согласования |
| Перенесена | Новое время + запрос повторного подтверждения |
| Отменена | Сообщение об отмене; подключение недоступно |
| Завершена | Материалы + опубликованные брокером следующие шаги |

Запрос переноса НЕ меняет время автоматически — брокер согласовывает слот. Кнопку подключения показывать, напр., за 15 мин до начала (параметр агентства); не зависит от того, нажал ли клиент подтверждение.

## 7. Что фиксируется в CRM (события в карточке лида/встречи)
Приглашение опубликовано · отправлено через канал · клиент подтвердил · запросил перенос · оставил вопрос · открыл материал · нажал «Подключиться». Нажатие Zoom ≠ фактическое присутствие (подтверждает брокер / видеосервис). Просмотры страницы — вспомогательная статистика (автопревью мессенджеров открывают ссылку без клиента).

## 8. Автоматизация
Шаблон агентства по умолчанию; персональная визитка из профиля брокера; сохранение своего варианта приветствия; дублирование оформления для другой встречи без копирования чужих клиентских данных; напоминания по сценарию; уведомление брокеру о подтверждении/вопросе/переносе; задача на обработку запроса переноса; выбор существующей подборки без повторной загрузки PDF. Zoom подключён → создаём встречу через него; нет → брокер вставляет ссылку вручную. Интерфейс честно показывает, какой вариант используется.

## 9. Публикация, время, доступ
Изменения оформления → в черновик, у клиента после публикации. Перенос/отмена встречи → обновляют действующую страницу сразу после сохранения встречи. **Ссылка остаётся прежней при переносе.** Время хранится с часовым поясом; клиент видит подписанную зону и может переключить. Неизвестное имя → нейтральное приветствие. Ссылку можно отозвать/перевыпустить. Публичная страница noindex. Для чувствительных материалов — доп. проверка доступа. «Защищённая ссылка» — только при реальной реализации доступа.

## 10. Оформление
Тёплый светлый фон, чёрные кнопки, выразительные заголовки, спокойные карточки LumenCRM. Мобильный порядок: приветствие → дата и действие → брокер → программа → материалы (большое фото не отодвигает подтверждение вниз). Логотип — с пропорциями и воздухом. Нет качественной обложки → красивая текстовая композиция.

## Связь с текущим кодом (на старте реализации)
- Страница встречи УЖЕ есть: `/m/:id` (confirm/reschedule/ICS, кнопка подключения) — её расширять в этот документ, НЕ плодить новую.
- Встречи: `db.meetings` (at/dur/kind/status/link/zoomMeetingId); создание `/api/meetings`; genMeetingLink (Zoom/Meet выбор — уже сделано 10.10).
- Профиль брокера, подборки (`/p/:id`, presentation.js), бренд агентства — переиспользовать.
- Состояния (§6) ложатся на mt.status (scheduled/done/canceled + новые: pending_confirm/reschedule_requested/rescheduled).
