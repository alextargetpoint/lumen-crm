# Конструктор PDF/презентаций объектов — разбор клиента (Trust Phuket), правки

Источник: фидбэк клиента по браузерной версии презентации объекта. PDF отдельно не проверялся.
Главная проблема: сейчас это выгрузка данных из CRM в оформлении презентации. Основа приятная
(спокойные цвета, засечки в заголовках, аккуратные разделители), но ОТБОР информации и ПРАВИЛА
КОМПОНОВКИ требуют доработки.

ПОРЯДОК ИСПРАВЛЕНИЙ (важно): сначала валюты и противоречия данных → затем отбор квартир и
структура страниц → затем логотип, типографика и оформление. Иначе красивый шаблон продолжит
показывать неподготовленные данные.

## 1. Ошибки данных (заметнее дизайна) — ПЕРВЫМ
- В таблице соседствуют $110 000 и $5 185 000, встречается $8 554 200 → проверить валюты и
  преобразование цен. Похоже на смешение валют. Нельзя просто добавлять «$» ко всем значениям.
- В локации «0 мин» рядом с «3 minutes | Layan Beach» → хранить отдельно место/время/способ
  передвижения. Время не определено — СКРЫВАТЬ, а не выводить ноль.
- Бюджет клиента $100 000, предложение от $110 000, при этом «строго под ваш запрос» → явно
  обозначать превышение бюджета и объяснять выбор (минимум на $10k выше).
- Клиент покупает ДЛЯ СЕБЯ, а рекомендации про доходность/рост → акценты под цель: для жизни —
  расположение, планировка, инфраструктура, сроки.
- Телефон и email эксперта визуально склеились → разнести в отдельные строки/элементы.

## 2. Убрать бесконечную таблицу квартир (сейчас 72 строки)
Три уровня:
- Основная подборка: 3–5 выбранных квартир (планировка, площадь, цена, ключевая особенность,
  причина рекомендации).
- Обзор проекта: по типам (студии / 1BR / 2BR), диапазоны площадей и проверенных цен.
- Полный каталог: отдельно по кнопке «Посмотреть все квартиры» (фильтры, сортировка, номера юнитов).
PDF: полный каталог — опциональное приложение с пагинацией и повтором заголовков таблицы. НЕ
вставлять все 72 строки в одну страницу проекта.

## 3. Перераспределить информацию между страницами (равномерная структура)
- Персональная обложка: для кого, направление, краткий запрос.
- Знакомство с объектом: большое фото, название, район, цена, срок сдачи.
- Почему подходит: 3 аргумента под запрос + существенные ограничения.
- Пространство и инфраструктура: 2–3 фото + 4–6 преимуществ.
- Выбранные квартиры: 3–5 вариантов с понятным сравнением.
- Условия покупки: рассрочка/этапы оплаты (если данные есть).
- Финальные страницы брокера: эксперт, контакты, следующий шаг — ОДИН раз на всю подборку.
Для одного проекта страницу-разделитель «Проект 01 из 01» убрать.

## 4. Логотип: отдельный компонент под форму файла
- Горизонтальный знак с названием → естественные пропорции, без квадратной рамки.
- Компактная эмблема → небольшой знак + название агентства рядом.
- Белый лого на прозрачном → поверх затемнённой фотографии.
- Тёмный лого на прозрачном → на светлом фоне/светлой подложке.
- JPG с непрозрачным фоном → в брендовой зоне, согласованной с фоном.
Для этой презентации: белая прозрачная Trust Phuket на фотообложке; тёмная горизонтальная на
внутренних светлых страницах. Если только квадратные исходники — лучше светлая/тёмная полоса бренда,
чем квадрат на фото.
В кабинет добавить: основной лого + версия для тёмного фона; предпросмотр на фото/светлом/тёмном;
настройка размера и положения; обрезка внешних полей с предпросмотром; режим подложки (нет/светлая/
тёмная). Технически: сохранять пропорции, object-fit: contain, не растягивать/не обрезать. Удаление
непрозрачного фона — отдельная операция с подтверждением, не авто-фильтр.

## 5. Длинные преимущества — не теги
«В комплексе» сейчас колонка длинных плашек (выглядят как фильтры). Нужно:
- Сетка 4–6 пунктов с иконками, короткое название («Спа и йога», «Коворкинг», «Бассейны»).
- При необходимости — одна строка пояснения. Остальное — «Все удобства».
- Теги оставить только для коротких характеристик: «У моря», «Рассрочка», «С террасой».

## 6. Типографика и язык
- Один язык презентации (бренды можно сохранять). Сейчас RU-заголовки + EN-описания/преимущества,
  December 2027, Residential, off-plan, terrace.
- Краткая локация «Лаян, Пхукет»; полный адрес — в подробностях (не повторять многократно).
- Короткий заголовок «Sun Hills Layan», концепция — под ним.
- Показатель крупно: «до 15%», пояснение ниже обычным шрифтом (не разбивать «до 15% p.a.» на строки).
- Лимиты объёма текста + перенос на следующий блок при переполнении (не бесконечная страница).
- Длинное название проекта не повторять на соседних страницах.

## 7. Рекомендация менеджера должна добавлять смысл
Сейчас повторяет цену/доходность/рост; «самый доступный старт» при одном проекте не с чем сравнить.
Заменить на три пункта:
- Почему этот объект выбран для клиента.
- В чём выходит за рамки запроса.
- Что уточнить перед решением.
Прогнозы доходности/роста — с источником и оговоркой РЯДОМ с цифрой.

## 8. Браузерная версия ≠ стопка печатных листов
- Браузер: адаптивные секции, раскрытие подробностей, галерея, компактная навигация, кнопка связи.
- PDF: фиксированные страницы, контролируемый объём блоков, корректные переносы.
- Финал: не повторять контакты несколько раз; две страницы брокера с разными задачами —
  «Ваш эксперт» и «Обсудим объект / назначим показ».

## Затронутые файлы (ориентир)
- public/pres-templates.js — реестр шаблонов/секций, правила компоновки.
- public/pres-tokens.js — палитры/шрифты/токены.
- public/pres-styles.css — вёрстка секций, печать.
- public/presedit.js / presedit.css — редактор (логотип-компонент, выбор квартир, подложки).
- server/presentation.js — серверная сборка/PDF (print), биндинг данных, валюты.
- server/index.js — данные объекта (валюты/цены/локация/время), /pres роуты.

# ВТОРОЙ РАЗБОР (подборка Coralina + Layan Green Park, веб-десктоп)

Эта версия аккуратнее: нет таблицы на 72, тексты на русском, контакты брокера разделены. Остаются
ошибки компоновки и персонализации.

ПЕРЕДАТЬ В ПЕРВУЮ ОЧЕРЕДЬ:
1. Исправить отступы финальной страницы.
2. Убрать внутренние скроллбары в презентационных блоках.
3. Настроить кадрирование фотографий и нормальное размещение логотипа.
4. Ограничить длину заголовков и убрать названия пресетов из выдачи.
5. Сделать содержательное сравнение проектов.
6. Добавить проверку соответствия бюджету, цели и срокам ДО публикации.

Детали:
1. Финальный чёрный экран сломан: логотип в самом верхнем левом углу, заголовок/контакты от левого
   края, сверху огромная пустая область, отступы отличаются от других страниц → единый внутренний
   контейнер и поля на ВСЁ содержимое (вкл. логотип), выровнять по общей сетке.
2. Внутренняя прокрутка внутри страницы проекта (описание локации в маленьком блоке со скроллом, справа
   и ниже пусто) → убрать внутренний скролл; короткое описание — целиком; длинное — раскрытие кнопкой
   (веб) / доп. блок; для PDF проверить, что скрытый текст не теряется.
3. Обложка: обрезанный фрагмент надписи «…G BUILDING» в фото, размыто при увеличении, один кадр
   повторяется → для обложек брать исходные рендеры без рекламных надписей; выбор точки кадрирования
   отдельно для вертикали/горизонтали; предупреждение при низком разрешении; разные кадры для общей
   обложки и представления проекта.
4. Заголовок Coralina в 5 строк перекрывает фото → разделить: «The Title Coralina Kamala» + подзаголовок
   «Курортные апартаменты в 350 метрах от пляжа»; описание — отдельным абзацем; лимит заголовка 2–3
   строки + альт-компоновка для длинного текста.
5. Логотип маленький квадрат, на финале без отступов → горизонтальная версия с прозрачным фоном,
   отдельно для светлой/тёмной поверхности, сохранять пропорции, масштаб по видимому знаку. Квадратный
   исходник → продуманный брендовый блок, не аватарка. Убрать «EDITORIAL LUXURY» (имя стилизации) с
   обложки — оставить только в конструкторе.
6. Сравнение сравнивает только цену (две полоски + тех. пояснение «максимум в строке») → компактная
   таблица: Цена от / Превышение бюджета / Срок сдачи / Расположение / Причина выбора. Метку «Лучшее»
   (меньшая цена ≠ лучший объект) → «Ниже цена входа», тех. объяснение убрать из клиентской выдачи.
7. Подборка противоречит запросу: бюджет $100k, проект 1 дороже на 58%, проект 2 на 96%, но «собрана
   строго под них» → показывать как альтернативы с ЯВНЫМ обозначением увеличения бюджета; рассрочка ≠
   равенство бюджету. «Полгода+» vs цитата «в этом году хочу успеть» при дате подборки окт-2026 —
   уточнять: покупка или заселение.
8. Покупка ДЛЯ СЕБЯ, аргументы — для инвестора (аренда/доходность/рост) → первыми: удобство жизни,
   планировки, район, инфраструктура, сроки; инвест-показатели — доп. блок; рекомендация объясняет
   выбор, вкл. компромиссы по бюджету.
9. Нормализация данных: «0 мин» рядом с «350 m / 2 минуты / 20 минут / 1 км»; Nov 2027 / Residential /
   off-plan в русской презентации; доходность то «8%», то «от 8%», то «ожидаемая средняя»; рассрочка
   обещана, график не показан → разделить расстояние и время, не подставлять ноль, унифицировать язык
   и формулировки, рассрочку выводить только из заполненных данных.
