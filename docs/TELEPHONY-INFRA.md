# Телефонная инфраструктура Lumen на Telnyx — полный план

Строится ПОСЛЕ подтверждения базового звонка (Telnyx-пайплайн уже проверен прямым вызовом: ключ,
Voice API App «Lumen Calls», номер, Италия в Outbound Profile, баланс — рабочие). Ниже — всё, что нужно
агентству недвижимости, привязано к тому, что в Lumen УЖЕ есть, и к Telnyx API.

## Что уже есть в коде (переиспользуем, не пишем заново)
- **Geo-пул номеров:** `db.settings.telephony.fromNumbers` (массив с гео-тегами) + `pickFrom(geo)` — выбор
  «От» под регион клиента. `telnyxInitiateCall`/`e164` — исходящий звонок.
- **Поиск/покупка номеров:** `/api/telephony/numbers/search` (+ покупка) — сейчас Twilio-ориентировано, расширяем на Telnyx.
- **Учёт стоимости:** биллинг считает `telephonyMin` (addUsage) — свяжем с вебхуком `call.cost`.
- **Прогрев:** движки `/api/warmup/*` и `waGray.warmup` (это для WhatsApp-номеров, не PSTN — см. ниже).
- **«Пул номеров»** — страница здоровья канала.

## 1. Динамическая смена гео (caller-ID под регион клиента)
- Пул номеров по странам: Дубай (+971), Бали (+62), Пхукет (+66), Италия, США, РФ, UK…
- При звонке `pickFrom(lead.geo)` подбирает локальный номер под клиента (местный ID = выше дозвон).
- **Реализация:** расширить `pickFrom` на структуру `{number, geo, brokerId?, health, purchasedAt}`; в
  `telnyxInitiateCall` брать `from` из `pickFrom(lead.geo, lead.broker)`.
- **Ротация:** внутри одного гео крутить номера по кругу (round-robin / по наименьшей нагрузке за день),
  чтобы один номер не выжигался.

## 2. Прямая покупка номеров из админки (Telnyx)
- Telnyx API: `GET /v2/available_phone_numbers?filter[country_code]=IT&filter[features]=voice&filter[phone_number_type]=local`
  → `POST /v2/number_orders {phone_numbers:[{phone_number}]}` → авто-привязка к connection «Lumen Calls»
  (`PATCH /v2/phone_numbers/{id} {connection_id}`).
- **UI:** в «Настройки → Телефония» (или «Пул номеров») — поиск по стране/типу + «Купить» + авто-assign к
  Voice App. Уже есть каркас `/api/telephony/numbers/search` — добавить **Telnyx-ветку** (сейчас Twilio).
- **⚠️ Регуляторка:** EU/UK/UAE-номера требуют документы (regulatory bundle). US local — мгновенно. Показывать
  в UI, что номер «pending — нужны документы», и вести к загрузке.

## 3. Авто-замена выгоревших номеров
- **Мониторинг здоровья:** на каждый номер считаем answer-rate, кол-во звонков/день, сигналы (частые
  «no answer»/короткие сбросы = вероятный спам-флаг). Порог → статус `burned`.
- **Авто-действие:** `burned` → освободить (`DELETE /v2/phone_numbers/{id}`) + купить свежий в том же гео
  (п.2) + переназначить в пул. Уведомить владельца («номер +… выгорел, заменён на +…»).
- **Cost-safe:** лимит авто-покупок в день/период (иначе баг = гора номеров); всё логировать.

## 4. Отдельный номер под каждого брокера
- Поле `brokerId` в объекте номера пула. Звонки брокера идут с ЕГО номера (стабильный личный caller-ID —
  клиенты узнают, перезванивают).
- **UI:** в карточке брокера — «выдать номер» (поиск по гео + купить/назначить) и «показать номер».
- В `pickFrom(geo, brokerId)` приоритет: личный номер брокера в нужном гео → общий пул гео.

## 5. Прогрев / репутация номера (PSTN ≠ WhatsApp!)
- ⚠️ У **голосовых** номеров «прогрева перепиской», как у WhatsApp, НЕТ. Репутация PSTN держится иначе:
  - **STIR/SHAKEN** аттестация (у Telnyx есть) — подпись caller-ID, меньше «Spam Likely».
  - **Branded Calling** (Telnyx CNAM/брендированный вызов) — имя агентства на экране = выше дозвон.
  - **Плавный набор оборотов:** новый номер — не заливать сотней звонков в день сразу; наращивать объём.
  - **Ротация + гео-локальность** (п.1) — размазывает нагрузку, номера живут дольше.
- **Реализация:** включить STIR/SHAKEN и Branded Calling на Voice App; в пуле у нового номера — «мягкий
  дневной лимит» первые N дней (поле `warmupDay`, уже есть у номеров), затем снятие.

## 6. Кто платит (модель биллинга)
- **Managed Accounts** (`rollup_billing:false`): номера и звонки — на аккаунте КЛИЕНТА, Telnyx биллит его
  напрямую. Lumen оркеструет покупку/замену/ротацию по API на его managed-аккаунте. (После включения
  manager-режима у Telnyx — сейчас 403.)
- До Managed Accounts (тест/свой аккаунт): всё на платформенном ключе `TELNYX_API_KEY`.

## 7. Учёт стоимости и аналитика
- Voice App: **Enable Call Cost** (включено) → вебхук `call.cost`/`call.hangup` с ценой → `addUsage` →
  строка расхода в биллинге (см. `docs/CONSUMABLES-BILLING-ROUTING.md` про art.15/Managed Accounts).
- Метрики пула в «Пул номеров»: по каждому номеру — звонки, answer-rate, стоимость, здоровье, гео, брокер.

## Фазы реализации
1. **Ф1 (после подтверждения звонка):** Telnyx-ветка поиска/покупки номеров в админке + авто-assign к Voice App.
2. **Ф2:** гео-пул `{number,geo,brokerId,health}` + `pickFrom(geo,broker)` + ротация; номер под брокера.
3. **Ф3:** мониторинг здоровья + авто-замена (с лимитами) + уведомления.
4. **Ф4:** STIR/SHAKEN + Branded Calling + мягкий лимит нового номера; учёт стоимости из вебхука.
5. **Ф5:** перенос всего на Managed Accounts (номера/биллинг на клиенте).
